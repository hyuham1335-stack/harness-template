## 목적

**보고서는 런이 스스로에 대해 말하는 유일한 자리다.** 그리고 이 페이즈가
막는 실패는 하나다 — **재지 못한 것이 조용히 통과하는 것.**

## 진입 조건

- 07 이 `passed` 이고 `08_report_data.json` 이 있다
- **`grade == INCOMPLETE` 면 08 을 돌리지 않는다** — `ESCALATION.md` 가
  보고서를 겸한다 (§E12)
- `## 리뷰` 표의 「프로파일」·「07 escaped」, `## 비용과 시간` 의 「자진신고 모델
  (`model_used`)」은 실행기가 조립한다 — **리뷰어가 적어 낸 값이지 실측이 아니다**.
  재지 않은 것을 숫자로 적지 마라

## 절차

```
1. 08_report_data.json   너     서술 4절 + 선택 (<= 20KB)
2. report --out          정적   결정론 표 조립 + 필수 섹션 검사 + 서술 하한
3. 커밋 → pr --run-id    너     런 기록을 기능 PR 에 싣는다 (ADR-H052)
```

### 1번 — 08 은 diff 도 코드도 읽지 않는다

서술 입력은 `08_report_data.json` **하나뿐이다.** 전문은 파일 경로로만 가리킨다.
이 제약이 08 의 비용을 런 크기와 무관하게 만든다.

**서술은 네가 쓰고, 표는 실행기가 조립한다.**

| 실행기가 조립한다 (결정론) | 네가 쓴다 (서술) |
|---|---|
| 완료 등급 + **건너뛴 비차단 게이트 나열** | 문제 → 원인 → 해결 |
| 페이즈별 소요 — **벽시계 · 순 작업 · 에스컬레이션 대기 · 사람 판단 대기 · 형식 반려 수** — 라운드·수리 카운터, **모델 호출 수(근사)** · 자진신고 모델 | **계약이 어디서 부족했는가** — 가장 실행 가능한 산출이다 |
| `review05.status` · `need_more_context` · `truncated` (**런 누적**이다 — 마지막 라운드가 아니다) · 07 `/code-review` 와 escaped(05 가 낸 키를 가리키지 않은 Major+) | (선택) 결과 · 배운 점 · 05 리뷰 범위 · 다음 런에서 바꿀 것 |

### 2번

```bash
python scripts/pipeline/cli.py report --out docs/harness/pipeline/runs/{run_id}.md --run-id {run_id}
```

### 3번 — 런 기록은 기능 PR 에 실린다

`report` 가 exit 11 로 런을 닫으면 `docs/harness/pipeline/runs/{run_id}.md` 를
커밋하고 `pr --run-id` 를 다시 돌린다. 닫힌 런의 `pr` 는 06 record 로 이어지지
않는다 — PR 갱신뿐이다.

## 제출 형식

`{run_dir}/08_report_data.json` 하나. **20KB 이하다.**

```json
{"narrative": {"문제": "…", "원인": "…", "해결": "…",
               "결과": "(선택)", "배운 점": "(선택)"},
 "contract_gaps": "계약이 어디서 부족했는가",
 "review_scope": "(선택) 05 리뷰 범위가 적절했는가",
 "next_run": "(선택) 다음 런에서 바꿀 것"}
```

- **`문제`·`원인`·`해결`·`contract_gaps` 는 80자 이상이다.** 미달이면 보고서는
  쓰되 **exit 8** 로 되묻고 런을 닫지 않는다 — 등급은 건드리지 않는다
  (ADR-H052). 「계약이 부족한 곳이 없었다」도 왜 그렇게 보는지를 80자로 적는다 —
  짧은 답을 받으면 그 절이 빈 채로 굳는다
- **재지 않은 것을 숫자로 적지 마라.** 모르면 `미측정` 이라고 쓴다.
  이 리포의 규율이고, 보고서가 그것을 깨면 다음 런이 지어낸 값을 물려받는다
- 서술이 비어도 보고서는 나온다 — **필수 섹션이 빠져도 파이프라인을
  실패시키지 않는다.** 기록만 남긴다

## 금지

- **diff 나 소스를 읽지 마라.** 이유: 08 의 입력은 파일 하나이고, 그 제약이
  보고서 비용을 런 크기와 무관하게 만든다
- **숫자를 지어내지 마라.** 이유: 보고서는 다음 런의 입력이다. 추정치가
  실측처럼 적히면 그 값이 정책이 된다
- **런 기록을 커밋하지 않은 채 끝내지 마라.** 이유: `docs/harness/pipeline/runs/{run_id}.md`
  는 **기능 PR 에 실린다** — 커밋하고 `pr --run-id` 를 다시 돌려 PR 을 갱신한다
- **`INCOMPLETE` 인 런에서 08 을 돌리지 마라.** 이유: 에스컬레이션으로 멈춘
  런은 `ESCALATION.md` 가 보고서다. 그 위에 성공한 것 같은 문서를 얹지 않는다

## 실패 시

| 무엇 | 분류 | 어떻게 |
|---|---|---|
| `grade == INCOMPLETE` | — | **08 을 돌리지 않는다.** `ESCALATION.md` 가 보고서를 겸한다 (§E12) |
| 필수 섹션 누락 | — | 기록하고 산출한다 |
| 서술 4절 중 80자 미만 | 정책 | 보고서는 쓰되 **exit 8** — 같은 명령으로 다시 낸다. 등급 X. 닫힌 런의 재작성은 되묻지 않는다 |
| 같은 `run_id` 로 재개해 다시 씀 | — | **덮어쓴다.** 최종본이 맞다 |
| 이미 닫힌 런에 다시 `report` | — | 보고서를 **덮어쓰고 exit 0.** 전이는 한 번뿐이고 `run_closed` 도 하나뿐이다 |
| 07 이 아직 `passed` 가 아님 | — | **보고서는 쓰고 런은 닫지 않는다** (exit 0). 전이 조건은 이 파일의 `requires` 그대로다 |

**명세 미규정 하나 — 지어내지 않고 적어 둔다.** `gaps[]` 의 어휘가 열거형으로
정의돼 있지 않다. 코드의 `GAP_REASONS` 는 명세 전체에서 **모은 것**이지 명세가
한자리에 준 목록이 아니다.

**exit 11 을 누가 내는가 (M24).** `on_success` 가 `done` 인 페이즈를 통과시키는
커맨드가 낸다. 08 에서 그것은 `report` 다 — 페이즈는 자기 동사로 닫힌다: 04 는
`gate`, 08 은 `report`, 나머지는 제출이 곧 그 페이즈의 일이라 `record` 다.
`record --phase 08` 은 `report` 를 가리킨다.
