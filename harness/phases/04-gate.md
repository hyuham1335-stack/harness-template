## 목적

어댑터가 선언한 스테이지 체인을 돌리고, 실패를 **역할에 귀속**해 그 역할에게만
되돌린다.

두 가지가 이 페이즈의 값이다. 첫째, 재작업 루프 안에서 전체 회귀를 돌리지 않는다 —
루프 게이트는 스코프 실행까지이고 전체 회귀는 루프가 끝난 뒤 한 번이다. 둘째,
**실패를 모델이 다시 분류하지 않는다.** 게이트가 낸 소유자별 배정을 그대로 쓴다.

## 진입 조건

- 계약 파일이 필수 절을 담고 있다 (`no_contract` 모드가 아닌 한)
- 03 이 `passed` 다
- 소유 경계가 깨끗하다 — 03 에서 이미 봤지만 여기서 다시 본다. 앞선 페이즈가
  파일을 고치므로 사전 검사는 예측이지 보장이 아니다
- 어댑터의 스테이지들이 실재한다 (여기서는 **차단**한다)

## 절차

체인은 두 구간이다.

```
루프 구간:  compile → lint → check → scoped        (실패하면 즉시 멈춘다)
루프 종료 후: full → e2e · build · docs             (조건부)
```

1. 루프 구간을 순서대로 돌린다. 스테이지에 명령이 없으면(`cmd: null`)
   **"스킵됨"으로 기록한다 — 통과가 아니다.** 등급에 반영된다.
2. `scoped` 의 선택자는 계약에서 조립한다. **선택자는 테스트 이름이 아니라 파일
   경로다.** 이름 필터는 러너가 모든 파일을 수집·변환하고 환경을 세운 *뒤에*
   거르므로 비용을 줄이지 못한다 — 이 리포의 실측에서 이름 필터는 전체 대비
   100.2%, 경로 필터는 14.6%(6.8배 싸다)였다.
3. 실패하면 귀속 4단계를 돌린다.
4. 루프를 통과하면 전체 회귀를 한 번 돌리고 **테스트가 몇 개 돌았는지**를 별도
   신호로 본다. 빈 스위트는 통과하고, 통과는 초록불로 보인다.
5. 조건부 스테이지는 어댑터의 `when_touched` 가 맞을 때만 돈다.
6. 등급을 매기고 영수증(지문)을 남긴다.

### 귀속 4단계

**0. 인프라를 먼저 걸러낸다.** 어댑터의 인프라 실패 패턴에 걸리면 소유자는
`infra` 이고 **카운터를 소모하지 않는다.** 이걸 안 하면 외부 의존 미기동이 구현
역할의 실패로 오분류돼 예산을 태운다. 종료 코드가 0 이 아닐 때만 본다 — 무관한
경고 한 줄이 전량을 인프라로 만들면 안 된다.

**1. 컴파일·타입.** 오류 줄에서 뽑은 경로를 역할 소유 glob 에 맞춰 소유자를 정한다.

> **주의**: 테스트 쪽 컴파일 실패의 상당수는 **구현 역할이 계약 시그니처를 안
> 지켜서** 생긴다. 심볼 부재 패턴에 걸리고 그 심볼이 계약에 있으면 소유자를
> 기본 역할로 **강제한다.** 경로만 보고 테스트 역할에 보내면 매번 오귀속된다.

**2. 테스트.** 리포트 파서가 실패를 정규화하고, 스택에서 테스트가 아닌 첫
애플리케이션 프레임이 원인 유닛이다.

| 조건 | 소유자 |
|---|---|
| 단언이 아닌 예외 + 최상단 앱 프레임이 어느 역할 소유 | 그 역할 |
| 스키마·데이터 계열 메시지 | 기본 역할 |
| 단언·목 불일치 — 계약에 심볼 **없음** | 테스트 역할 `[out_of_contract]` |
| 단언·목 불일치 — 계약에 심볼 **있음** | `ambiguous` |

정규식 파싱은 완전할 필요가 없다. 못 찾으면 `ambiguous` 로 안전 낙하한다 —
**"틀린 확신"보다 "모른다"가 낫다.**

**3. 못 정하면 `ambiguous`.** 기본 역할에 먼저 보내고, 같은 실패 시그니처가
재발하면 다음 역할로 넘긴다(계약 원문과 현재 실제 시그니처를 함께 준다). 또
재발하면 계약 결함으로 재분류해 메인에게 올린다.

**단, 실패 프레임이 하나 이상이고 전부 테스트 파일이면 테스트 역할에 먼저
보낸다** (ADR-H072). 스텁 픽스처가 원인인 실패를 기본 역할에 보내면 구현이
스텁에 맞추려 **계약에 없는 분기를 프로덕션에 넣는다** — 오배정의 대가가
「라운드 하나」가 아니라 프로덕션 코드 오염이다.

**넘길 역할은 순서 번호가 아니라 「아직 안 시도한 것」으로 고른다**
(ADR-H072). 사다리 순서가 그 실패의 프레임에 따라 라운드마다 달라질 수 있고,
번호로 고르면 뒤집힌 사다리가 한 역할을 통째로 건너뛴다.

**동시 배정을 하지 않는다.** 03 의 병렬이 안전했던 것은 소유가 겹치지 않고 계약이
고정됐기 때문이다. 수리는 "같은 하나의 동작"을 두고 다투는 상황이라, 동시에
보내면 구현은 테스트에 맞춰 구현을 바꾸고 테스트는 구현에 맞춰 테스트를 바꾸는
핑퐁이 나고 **둘 다 계약에서 멀어진다.** 예외는 실패 집합이 대상을 공유하지 않는
경우다.

## 역할 프롬프트 템플릿

수리는 **한 역할에게만** 간다. 게이트가 정한 소유자를 그대로 쓰고, 다시 정하지 않는다.

```
## 수리 지시 — {owner}

게이트 {round}회차에서 아래가 실패했다. 배정 근거: {owner_reason}

{실패당 60줄 이내의 브리프 — 유닛 · 파일 · 메시지 · 앱 프레임}

전문은 `{dispatch_file}` 에 있다.

## 계약에서 관련된 부분
{계약 발췌 — 이 실패가 걸린 유닛·진입점·오류 어휘만}

## 네 소유 경계
| 역할 | 소유 | 제외 |
|---|---|---|
| {role.id} | {role.owns} | {role.excludes} |

## 규칙
- 이 브리프의 실패만 고친다. 다른 실패는 네 것이 아니다
- 실패를 다시 분류하지 마라 — 배정은 이미 끝났다
- 계약이 틀렸다고 판단되면 고치지 말고 CONTRACT_DEFECT 로 보고한다
```

배정이 `ambiguous` 에서 왔다면 그 사실을 `owner_reason` 에 적는다. 같은 실패가
재발해 다음 역할로 넘어갈 때는 **계약 원문과 현재 실제 시그니처를 함께** 준다 —
넘겨받은 역할이 무엇을 맞춰야 하는지 알아야 핑퐁이 아니라 수렴이 된다.

## 제출 형식

모델이 이 페이즈에 파일을 제출하지 않는다. 게이트가 스스로 리포트를 쓰고, 모델은
봉투의 수리 지시를 받아 **해당 역할에게만** 되돌린다.

## 금지

- **실패를 다시 분류하지 마라.** 이유: 게이트가 낸 소유자별 배정이 결론이다.
  모델이 재분류하면 핑퐁 방지와 시그니처 추적이 무너진다
- **테스트를 지우거나 건너뛰기 표시로 통과시키지 마라.** 이유: 테스트 수가 캘리브
  레이션 대비 급감하면 게이트가 차단한다. 그리고 그것이 이 게이트의 존재 이유다
- **스테이지 명령을 직접 실행하지 마라.** 이유: 실행은 어댑터를 통해서만 한다.
  직접 돌린 결과는 영수증에 남지 않아 지문 대조가 성립하지 않는다
- **소스를 고친 뒤 게이트를 다시 돌리지 않고 넘어가지 마라.** 이유: 워크트리
  지문이 어긋나 다음 전이가 거부된다. 막히는 것이 정상 동작이다

## 실패 시

| 무엇 | 분류 | 어떻게 |
|---|---|---|
| 인프라 패턴 매칭 | infra | 카운터 미소모 · 즉시 에스컬레이션 |
| 리포트를 한 건도 못 찾음 | infra | 경로 설정 오류일 수 있다. 카운터 미소모 |
| 테스트 0개 | 비차단 | 등급 `PASS_WITH_GAPS` + 보고서 명시. 첫 런은 여기가 정상 |
| 테스트 수 급감 | 차단 | 삭제·스킵 의심 → 수리 루프 |
| 스테이지 실패, 예산 남음 | 제출물 | exit 4 — 소유자에게 수리 지시 |
| 스테이지 실패, 예산 소진 | 제출물 | exit 5 → 에스컬레이션 |
| 동일 `(소유자, 시그니처)` 쌍 2회 | 정책 | **예산이 남아도** 즉시 에스컬레이션 |

**세는 단위는 시그니처가 아니라 쌍이다.** ambiguous 실패의 시그니처는 소유자가
`"ambiguous"` 로 굳어 라운드를 넘어 안 바뀐다. 시그니처만 세면 flip 이 다음
역할을 배정한 바로 그 라운드에 정체 감지가 먼저 멈추고, 그 배정이 지시로 나가지
못한 채 버려진다 — 두 역할 중 한쪽만 시도해 보고 끝난다 (M33).

그래서 ambiguous 실패는 사다리(`primary_role` → 다음 역할 → 계약 결함)를 오르는
동안 **수리 상한 3 이 먼저 닫을 수 있다.** 의도한 것이다 — "예산을 다 썼다" 가
"같은 자리를 맴돈다" 보다 정직한 이유다.

**수리 상한 3 과 `stuck_after_identical: 2` 는 미검증 상속값이다.** 첫 세 런의
원장이 이 값을 검사한다. 다만 `stuck_after_identical` 은 **이제 코드가 실제로
읽는다** — 예전에는 여기 선언만 있고 `2` 가 코드에 박혀 있어 값을 바꿔도 동작이
변하지 않았다. **`counter` · `max` · `on_exceed` 도 같아졌다** (M36): 코드에
`or` 폴백이 없으므로 선언을 지우면 조용히 기본값으로 낙하하는 대신 exit 2 다.
