## 목적

어댑터가 선언한 스테이지 체인을 돌리고, 실패 출력을 **작성자에게 그대로**
되돌린다.

이 페이즈는 영수증이다. 작성자는 03 에서 typecheck·lint·테스트를 직접 돌려 확인해도
되지만 그 실행은 기록에 남지 않는다 — 04 가 같은 스테이지를 **한 번 더** 돌려
`04_gate_report.json` 에 남긴다. 작성자의 「통과했다」를 믿지 않는 자리다.

두 가지가 이 페이즈의 값이다. 첫째, 재작업 루프 안에서 전체 회귀를 돌리지 않는다 —
루프 게이트는 스코프 실행까지이고 전체 회귀는 루프가 끝난 뒤 한 번이다. 둘째,
**실패를 분류하지 않는다.** 작성자가 하나이므로 누구의 실패인지 물을 것이 없고,
실패 스테이지의 출력이 그대로 수리 지시다 (ADR-H075).

## 진입 조건

- 계약 파일이 필수 절을 담고 있다 (`no_contract` 모드가 아닌 한)
- 03 이 `passed` 다
- 어댑터의 스테이지들이 실재한다 (여기서는 **차단**한다)

## 절차

체인은 두 구간이다.

```
루프 구간:  compile → lint → check → scoped        (실패하면 즉시 멈춘다)
루프 종료 후: full → e2e · build · docs             (조건부)
```

1. 루프 구간을 순서대로 돌린다. 스테이지에 명령이 없으면(`cmd: null`)
   **"스킵됨"으로 기록한다 — 통과가 아니다.** 등급에 반영된다.
2. `scoped` 의 선택자는 계약에서 조립한다. **선택자는 테스트 이름이 아니라 파일
   경로다.** 이름 필터는 러너가 모든 파일을 수집·변환하고 환경을 세운 *뒤에*
   거르므로 비용을 줄이지 못한다 — 이 리포의 실측에서 이름 필터는 전체 대비
   100.2%, 경로 필터는 14.6%(6.8배 싸다)였다.
3. 실패하면 먼저 **인프라를 걸러낸다.** 어댑터의 `infra_failure_patterns` 에 걸리면
   외부 의존의 문제다 — **카운터를 소모하지 않고** 에스컬레이션한다. 종료 코드가
   0 이 아닐 때만 본다. 아니면 `repair` 를 하나 쓰고, 실패 스테이지의 출력
   브리프(끝 60줄)를 봉투에 실어 작성자에게 되돌린다. 3회를 넘으면 에스컬레이션이다.
4. 루프를 통과하면 전체 회귀를 한 번 돌리고 **테스트가 몇 개 돌았는지**를 별도
   신호로 본다. 빈 스위트는 통과하고, 통과는 초록불로 보인다. 하한은 **직전 완주
   런의 `tests.ran` × 0.9** 다 — 급감하면 차단하고 같은 브리프로 되돌린다.
5. 조건부 스테이지는 어댑터의 `when_touched` 가 맞을 때만 돈다.
6. 등급을 매기고 영수증(지문)을 남긴다.

## 역할 프롬프트 템플릿

수리는 **작성자에게** 간다. 봉투의 브리프를 그대로 싣고, 요약하지 않는다.

```

## 규칙
- 이 출력의 실패만 고친다. 테스트를 구현에 맞추지 말고 구현을 테스트에 맞춘다
- 테스트를 지우거나 건너뛰기 표시로 초록을 만들지 마라 — 테스트 수 급감은 차단이다
- 계약이 틀렸다고 판단되면 고치지 말고 CONTRACT_DEFECT 로 보고한다
- 고친 뒤 typecheck·lint·테스트를 직접 돌려 확인하고 제출한다 — 영수증은 게이트가 남긴다
```

## 제출 형식

모델이 이 페이즈에 파일을 제출하지 않는다. 게이트가 스스로 리포트를 쓰고, 모델은
봉투의 수리 지시를 받아 **작성자에게** 되돌린다.

## 금지

- **출력을 요약해 없애지 마라.** 이유: 실패 출력이 곧 수리 지시다. 요약하면 작성자가
  다른 것을 고친다
- **테스트를 지우거나 건너뛰기 표시로 통과시키지 마라.** 이유: 테스트 수가 직전
  완주 런 대비 급감하면 게이트가 차단한다. 그리고 그것이 이 게이트의 존재 이유다
- **스테이지 명령을 직접 실행하지 마라.** 이유: 실행은 어댑터를 통해서만 한다.
  직접 돌린 결과는 영수증에 남지 않아 지문 대조가 성립하지 않는다
- **소스를 고친 뒤 게이트를 다시 돌리지 않고 넘어가지 마라.** 이유: 워크트리
  지문이 어긋나 다음 전이가 거부된다. 막히는 것이 정상 동작이다

## 실패 시

| 무엇 | 분류 | 어떻게 |
|---|---|---|
| 인프라 패턴 매칭 | infra | 카운터 미소모 · 즉시 에스컬레이션 |
| 리포트를 한 건도 못 찾음 | infra | 경로 설정 오류일 수 있다. `test_report_missing` gap · 카운터 미소모 |
| 테스트 0개 | 비차단 | 등급 `PASS_WITH_GAPS` + 보고서 명시. 첫 런은 여기가 정상 |
| 테스트 수 급감 | 차단 | 삭제·스킵 의심 → exit 4, 같은 브리프로 작성자에게 |
| 스테이지 실패, 예산 남음 | 제출물 | exit 4 — 실패 출력 브리프를 작성자에게 |
| 스테이지 실패, 예산 소진 | 제출물 | exit 5 → 에스컬레이션 (선택지 없이 자유 서술) |

**수리 상한 3 은 미검증 상속값이다.** 실측이 이 값을 검사한다. **`counter` · `max` ·
`on_exceed` 는 코드가 여기서 읽는다** (M36): `or` 폴백이 없으므로 선언을 지우면
조용히 기본값으로 낙하하는 대신 exit 2 이고, 그 사실을 `lint-phases` 가 런 전에
먼저 잡는다.
