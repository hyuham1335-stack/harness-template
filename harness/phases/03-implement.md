## 목적

계약을 고정하고, **작성자 하나**가 계약대로 테스트를 먼저 쓰고 구현한다.

> **계약이 먼저 고정하고, 테스트가 그다음이다.**
>
> 메인이 단독으로 쓴 계약이 시그니처·오류 어휘·진입점을 먼저 고정한다. 작성자는
> 그 계약을 보고 **유닛·진입점·오류 어휘마다 테스트를 먼저 쓰고 빨간불을 확인한
> 뒤** 구현해 초록으로 만든다. 테스트가 구현을 보고 사후에 맞춰지는 것을 막는
> 것은 순서이지 역할 분리가 아니다 — 분리했을 때는 테스트가 코드를 못 보고
> 쓰여 스텁 행 불일치와 「아무것도 잠그지 않는 테스트」가 났다 (ADR-H075).
>
> 작성자는 typecheck·lint·테스트를 **직접 돌려 확인해도 된다.** 그것은 자기
> 확인이고 기록에 남지 않는다 — 04 가 같은 스테이지를 한 번 더 돌려 영수증을
> 남긴다. 작성자의 「통과했다」는 04 가 믿지 않는다.

## 진입 조건

- 01 이 `passed` 다
- 플랜이 있다
- 계약 파일이 있고 필수 절을 담고 있다 (`no_contract` 모드가 아닌 한)

## 절차

1. **메인이 계약 파일을 직접 쓴다.** 작성자에게 위임하지 않는다. 템플릿은
   `harness/templates/contract.md` 이고 절 제목은 `config.contract.sections` 가
   단일 출처다. 한쪽만 고치면 계약 추적이 조용히 아무것도 못 찾고 통과한다.
   **`## 유닛`·`## 진입점` 은 최상위 `- ` 불릿 하나에 항목 하나다.** `### `
   헤딩·들여쓴 불릿·산문은 파서가 유닛으로 세지 않는다 — 유닛이 0 인 계약은
   `record` 가 exit 8 로 거부한다 (ADR-H049). 진입점 경로의 파라미터는 `{id}` 로
   적어도 어댑터 `param_styles` 가 실제 폴더명(`[id]`)으로 찾는다.
2. **패킷의 역할 하나를 부른다.** 봉투 헤더의 `역할: impl→impl-writer` 가 그것이다.
   아래 역할 프롬프트 템플릿을 채워 준다 — 패킷에 **소유권 표**가 들어 있고, 그
   표가 소유 경계의 유일한 출처다.
3. 작성자의 제출물을 `03_claims.json` 으로 낸다. 형식은 아래 「제출 형식」이다 —
   `claimed_files` 는 정보이고 검사하지 않는다.
4. 컴파일 게이트를 돌리고, 이어서 **테스트 존재 검사**(`tests_required` —
   진입점·오류 어휘의 테스트)를 05 계약 대조와 같은 함수로 돌린다. 빠지면 첫
   런부터 exit 8 이다 — 유예가 없다 (ADR-H058). 05 의 Major 는 수리 루프를
   돌리지 않으므로 여기서 요구해야 고쳐진다. 목록은 패킷의 「게이트가 세는
   테스트」 절이 계약에서 뽑아 준다 — 작성자에게 그대로 넘긴다.

### docs 레인 — 역할 0명 (ADR-H044)

`docs` 레인을 선언한 런은 **작성자를 부르지 않고 계약도 쓰지 않는다**
(`allow.unless` · `state.contract.mode == "no_contract"`). 메인이 직접 문서를
고치고 `03_claims.json` 을 `{"schema":1,"roles":[]}` 로 낸다.

**역할 소유 경로(소스)를 건드리면 제출이 exit 3 으로 되돌아온다.** 선언이
빗나간 것이다 — 프로파일이 `normal` 로 오르고 `lane_miss` 가 gap 으로
남으며(01 리뷰어 · 작성자를 건너뛴 채 여기까지 왔으므로), 계약을 쓰고
`next` 로 역할 패킷을 받는다.

## 제출 형식

```json
{"schema":1,"roles":[
  {"role":"impl","agent":"impl-writer","status":"ok|blocked",
```

이유를 적는다.

## 금지

- **계약을 작성자에게 쓰게 하지 마라.** 이유: 계약은 메인 단독 소유이고,
  구현자가 계약을 쓰면 계약이 구현을 따라간다
- **소유 경계 밖의 파일을 만들거나 고치지 마라.** 이유: 하네스 자신·문서·설정은
  메인 단독 소유다. 워커가 고치면 게이트가 검사할 기준이 게이트를 통과하려고 바뀐다
- **계약이 틀렸다고 고치지 마라.** 이유: 발견은 값지지만 수정은 메인의 몫이다.
  `CONTRACT_DEFECT` 로 보고하면 메인이 고치고 델타를 다시 내린다
- **테스트를 구현에 맞추지 마라 — 구현을 테스트에 맞춘다.** 이유: 테스트는
  계약을 잠그는 것이고, 구현을 보고 고친 테스트는 아무것도 잠그지 않는다. 계약이
  틀려서 못 맞추면 `CONTRACT_DEFECT` 다
- **테스트를 지우거나 건너뛰기 표시로 초록을 만들지 마라.** 이유: 테스트 수가
  직전 완주 런보다 급감하면 04 가 차단한다. 그리고 그것이 이 게이트의 존재 이유다
- **커밋·푸시하지 마라.** 이유: 파이프라인이 지문을 잡는 시점이 정해져 있고,
  중간 커밋은 그 지문을 앞당겨 게이트 영수증을 어긋나게 한다

## 실패 시

| 무엇 | 어떻게 |
|---|---|
| 계약의 유닛이 0 | exit 8 — 봉투가 형식과 버려진 줄을 보여 준다. 계약을 고치고 같은 명령 |
| 컴파일 실패 | exit 4 — 출력 앞부분(2,000자)을 작성자에게 그대로 되돌린다 |
| 게이트가 세는 테스트가 없다 | exit 8 — 어느 진입점·오류 어휘의 테스트가 빠졌는지 봉투에 나온다. 작성자가 더하고 같은 명령 |
| 계약 결함 보고 | 메인이 계약을 고치고 델타를 내린다. 카운터를 소모하지 않는다 |
