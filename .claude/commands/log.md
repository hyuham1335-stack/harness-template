> **이 커맨드는 승격만 한다.** 사실 수집은 `SessionEnd` 훅이
> `scripts/session_log.py` 로 이미 했고, 여기서 하는 일은 **그 사실을 사람이
> 읽는 문장으로 옮기는 것**뿐이다. 원장이 모르는 것을 여기서 지어내면 이
> 자동화가 문서의 신뢰를 없앤다.

대상: $ARGUMENTS

인자가 비어 있으면 **승격되지 않은 것 전부**를 본다.

---

## 0. 원장을 읽는다

```bash
cat docs/pipeline-ledger.jsonl
```

- `"promoted": false` 인 줄이 후보다. 세션 시작 때 `미승격 세션 N개` 가 떴다면
  그 N 이 이 절의 후보 수다 (`session_log.py --pending`).
- 뒤에 `{"promote": …}` 줄이 있으면 그 줄이 가리키는 세션은 **이미 승격된 것**이다.
- **원장이 비어 있거나 구멍이 있으면 `git log` 로 직접 읽는다.** 크래시나 창
  닫기로 훅이 안 돌았을 수 있고, 그때 아무것도 못 하면 이 커맨드는 쓸모가 없다.
  그 경우 승격한 항목에 **근거가 원장이 아니라 git 이었다는 것**을 적는다.

## 1. 후보가 실제로 무엇을 했는지 본다

원장 줄의 `commits[].sha` 를 그대로 쓴다.

```bash
git show --stat --format="%H%n%s%n%n%b" <sha>
```

`commits_since.kind` 를 반드시 확인한다 — `prev_entry` 면 직전 기록 이후,
`base_branch` 면 브랜치 전체, `head_recent` 면 그냥 최근 것이다. **셋은 서로
다른 뜻이고, 섞으면 숫자가 거짓이 된다.**

## 2. §5 에 한 줄을 올린다

`docs/PIPELINE-LOG.md` 의 `## 5. 발생한 문제와 해결` 표에 행을 추가한다.

```
| **M24** | {무엇이 잘못돼 있었나 — 그리고 그게 무엇을 조용히 통과시킬 뻔했나} | {어떻게 고쳤나 — 그리고 왜 그 방법인가} | `{sha}` (테스트 {before} → {after}) |
```

- ID 는 기존 최대 번호 다음이다. 파이프라인 결함이 아니면 `후속` 처럼 적는다.
- **결론의 형태를 기존 항목과 맞춘다** — 표 머리글이 "이 결함이 무엇을 조용히
  통과시킬 뻔했는가"로 통일돼 있다.
- 테스트 수는 원장의 `tests.app` 과 `run.*` 에서 온다. **없으면 적지 않는다.**
- **`run.basis` 가 `latest_only` 인 줄의 `run.*` 는 그 세션의 사실이 아니다** — 런은
  있었지만 이 세션이 만진 적이 없다는 뜻이다 (M59 · [[ADR-H036]]). `tests.source` 도
  그때는 `calibration` 이다. `basis` 칸이 아예 없는 줄은 **판정 불가**이고, 2026-09-10
  이전 줄이 전부 그렇다 — 그 줄들의 `run.*` 는 남의 런일 수 있으니 믿지 않는다.

## 3. 어긋난 표를 같이 고친다

- **§1 규모 표** — 테스트 건수·줄 수. 실물과 다르면 고친다.
- **§6.5 훅 표** — 훅을 더하거나 뺐으면 고친다. 이 표는 자기 현황을
  주장하므로, 안 고치면 **문서가 즉시 거짓이 된다.**

## 4. 승격을 원장에 표시한다

```bash
python - <<'EOF'
import io, json
from datetime import datetime
rec = {"promote": {"ts": datetime.now().astimezone().strftime("%Y-%m-%dT%H:%M:%S%z"),
                   "sessions": ["<session_id>"], "entry": "M24"}}
with io.open("docs/pipeline-ledger.jsonl", "a", encoding="utf-8", newline="") as f:
    f.write(json.dumps(rec, ensure_ascii=False) + "\n")
EOF
```

## 금지

- **원장에 없는 것을 §5 에 적지 마라.** 이유: 이 문서의 머리가 "추정치를
  실측처럼 쓰지 않는다"이고, 자동 기록이 그 규율을 먼저 깨면 문서 전체의
  신뢰가 사라진다.
- **원장의 기존 줄을 고치거나 지우지 마라.** 이유: append-only 라야 머지
  충돌이 union 으로 자명하게 풀린다 (`team-spec.md` §5.2).
- **`docs/harness/**` 를 고치지 마라.** 이유: 프로젝트 작업 중에는 읽기
  전용이다 (`CLAUDE.md`).
- **커밋 하나를 두 항목으로 쪼개지 마라.** 이유: §5 의 ID 가 결함 하나를
  가리키는 신원이고, 쪼개면 같은 결함이 두 번 학습된다.
- **테스트를 돌려 수치를 새로 만들지 마라.** 이유: 원장이 기록한 시점의
  값과 지금 값이 다르면 그 차이가 어디서 왔는지 아무도 모른다.
