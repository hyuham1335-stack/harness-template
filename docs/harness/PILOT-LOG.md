# 파일럿 기록 (Pilot Log)

> **이 문서의 위치**
> 하네스 자체의 문서다. `docs/` 직속 7종(프로젝트가 채우는 자리)과는 층이 다르다.
> [ROADMAP.md](ROADMAP.md) 2단계의 승격 조건이 이 문서이며, 여기 적힌 실측이
> [ROADMAP.md](ROADMAP.md) §6 표를 움직이는 **유일한 근거**다.
> **추정치를 적지 않는다. 재보지 않은 것은 「미측정」으로 남긴다.**

> **런 기록은 비어 있다.** 템플릿을 만든 파일럿의 런 기록은 추출 이력(`git log`)에
> 있고, 팁에서는 걷어냈다 — 남의 실측을 상속하지 않기 위해서다
> ([ADR-H039](DECISIONS.md)). 아래는 **한 런이 무엇을 남겨야 하는가**의 형식과
> 첫 실물런 전에 적어 둔 예측이고, 첫 런이 「런 기록」 아래에 자기 절을 연다.

---

## 무엇을 여기 적는가

**런 하나 = 절 하나.** 런이 끝난 직후에 적고, 나중에 기억으로 채우지 않는다.

| 적는 것 | 적지 않는 것 |
|---|---|
| 기계가 낸 숫자 (소요·테스트 수·카운터·종료 코드) | 어림·기억·"대략 이 정도였다" |
| 사람이 개입한 자리와 **왜** 개입했나 | 개입을 뭉갠 "완주했다" |
| 예측을 **먼저** 적고 결과와 대조한 표 | 사후에 맞춘 해석 |
| 실패(시스템이 못 함)와 결과 없음(데이터가 없음)을 **가른** 서술 | 둘을 같은 칸에 넣은 요약 |

**스킵은 통과가 아니다.** 못 잰 스테이지는 「미측정」으로 남기고, 그 값에서
유도되는 정책이 보수적 기본값으로 간다는 사실을 함께 적는다.

## 런 절의 형식

새 런은 아래 골격을 복사해 채운다. **빈 칸을 지우지 말고 「미측정」으로 남긴다** —
칸이 사라지면 재본 적 없다는 사실도 같이 사라진다.

칸은 출처로 나뉜다. **08 보고서**(`docs/harness/pipeline/runs/{run_id}.md`)가 이미
내는 것은 옮겨 적기만 하고, 08 이 내지 않는 것은 사람이 런 디렉터리에서 찾아 적는다.

```markdown
## 파이프라인 런 P{N} — `{기능 이름}` ({날짜})

### 사람이 적는 칸

| 항목 | 값 | 출처 |
|------|-----|------|
| 일자 | | `state.created_at` |
| 런 ID | `_workspace/runs/{run_id}` | |
| 브랜치 | (base ) | `config.vcs.base_branch` · `state.pr` |
| 대상 | (계약의 유닛·진입점) | `04_gate_report.json` 의 `contract` |
| 어댑터 | | `state.adapter.id` |
| 변경 줄 수 | | `state.precheck.at_05.lines` |
| 머신 | OS · python · 러너 · 로캘 | 어디에도 기록되지 않는다 |

### 08 보고서에서 옮기는 칸

| 항목 | 값 | 08 의 자리 |
|------|-----|------|
| 등급 | | `## 완료 등급` |
| 건너뛴 게이트 | | `## 건너뛴 게이트` |
| 런 wall (합계) | | 페이즈별 소요 표의 합계 — 벽시계 · 순 작업 · 두 종류 대기 |
| 페이즈별 소요 | | 같은 표의 페이즈 행 |
| 모델 호출 | 총 / 페이즈별 | `## 비용과 시간` |
| 카운터 | round · repair · review_repair · trace_repair (사유) | 같은 표 |
| 테스트 | 실행 수 · 상태 | 같은 표 |
| 형식 반려 | | 페이즈별 소요 표 |
| 프로파일 | (lane_miss 여부) | `## 리뷰` |
| 01 기각 | | `## 리뷰` 「01 기각(false_positive)」 |
| 05 | status · 리뷰어 ok/planned · 절단 · 맥락 부족 | `## 리뷰` |
| 07 escaped | 건수 (findings · dup_05) | `## 리뷰` + 개별 목록 |

### 스테이지 실측

08 은 스테이지 단위를 내지 않는다. 사람이 런 디렉터리에서 옮긴다 — **게이트
호출마다 `events.jsonl` 의 `gate_stages` 이벤트** 하나(`phase` · `selector` ·
`stages[]` 의 `id` · `state` · `exit` · `sec`)가 남는다. 04 의 앞 회차와 05 의
재게이트(`--stage loop|full`)도 여기 있다. 테스트 수는 `04_gate_report.json`
(04 마지막 회차)이나 `state.tests`(마지막 full)에서 본다.

| 스테이지 | 소요 | 종료 코드 | 테스트 | 비고 |
|---|---:|---:|---:|---|

### 이 런이 확인하기로 했던 것 — 그리고 결과

**런 전에 적은 예측**과 실측을 나란히 둔다. 예측을 먼저 적었기 때문에 이 대조가
사후 합리화가 아니라 채점으로 남는다. 첫 실물런은 아래 「첫 실물런 전 예측」 표를 쓴다.

### 막힌 지점 · 수동 개입

파이프라인이 멈춰 사람에게 물은 자리. **상태를 잠갔는지**까지 적는다. 08 은 대기
시간과 건수만 낸다 — 사유는 `ESCALATION.md` 와 `events.jsonl` 의 `escalated` ·
`waiting_human` 에 있다.

### 이 런이 연 하네스 결함

| ID | 무엇 | 상태 |
|---|---|---|

### 이 런이 ROADMAP §6 표에 주는 답

[ROADMAP.md](ROADMAP.md) §6 의 「검증된 것과 아직 아닌 것」 표 중 어느 줄이
움직였나. **안 움직였으면 안 움직였다고 적는다.**

### 다음 런에서 볼 것

(08 의 「다음 런에서 바꿀 것」에서 옮기고, 사람이 더한다)
```

## 첫 실물런 전 예측 (ADR-H075)

[ADR-H075](DECISIONS.md) 가 덜어내기의 결과를 **첫 실물런 전에** 적어 두라고 한
여덟 줄이다. 런 뒤 「결과」 칸을 채워 채점한다.

기준선은 **클론 리포 `banana-island-ops` 의 4런(P2~P5, 2026-09-20)** 이다 — 템플릿의
값이 아니라 그 리포의 실측이고, 이 표가 그 숫자를 상수로 물려받지 않는다
([ROADMAP.md](ROADMAP.md) §6 · [ADR-H039](DECISIONS.md)).

| # | 예측 | 기준선 (banana-island-ops P2~P5) | 이 런에서 읽을 곳 | 결과 |
|---|---|---|---|---|
| 1 | 런 wall ≤ 40분 | 중앙 61.5분 (48.1 · 39.4 · 74.9 · 81.6) | 08 페이즈별 소요 합계 | |
| 2 | 지시된 모델 호출 ≤ 8 | 중앙 13.5 | 08 모델 호출 | |
| 3 | `format_reject` 0 — 남는 생산자는 01·05 의 `check_review` 뿐 | 4런 합 4 (출처였던 02·`rules_read` 는 소멸) | 08 형식 반려 | |
| 4 | 03+04 분 ÷ 변경 줄 수 ≤ 기준 중앙값 × 1.3 = **1.86분/100줄** | 아래 표 — 중앙 1.43분/100줄 | 08 의 03·04 벽시계 ÷ `state.precheck.at_05.lines` (줄 수는 08 밖) | |
| 5 | 04 수리 ≤ 1회 | P5 2회 | 08 카운터 `repair` | |
| 6 | gen 이 Critical 을 낸다면 그 종류(계약 대조 · SQL 정독)를 적는다 | P4·P5 는 gen 이 전부 잡았다 | `state.phases["05-code-review"].rounds` 의 gen `findings` (08 밖 — `05_review_gen.json` 은 마지막 라운드만 남는다) | |
| 7 | 07 `/code-review` 의 `dup_05=false` Major+ 건수 | 옛 `escaped_05`(07 의 비중복 Critical+Major) — 클론 08 보고서 재셈 13건 / 표본 9런 = **1.44/런** (critical 2) | 08 「07 escaped」 | |
| 8 | gen 이 내는 `TEST_MISSING_FAILURE_PATH` findings 수 | 리뷰어 48건 / 4런 = **12.0/런** (P2~P5 = 15 · 5 · 14 · 14) | 예측 6 과 같은 곳 (08 밖) | |

**예측 4 의 기준선.** 03+04 벽시계는 `state.phase_durations` 의 `wall_sec` 합이고 네 런 모두
대기가 0 이었다. 줄 수는 `state.precheck.at_05.lines` 다.

| 런 | run_id | 03+04 분 | `at_05.lines` | 분/100줄 |
|---|---|---:|---:|---:|
| P2 | `20260919-2342-9258` | 18.83 | 951 | 1.98 |
| P3 | `20260919-2343-d42d` | 15.42 | 2,842 | 0.54 |
| P4 | `20260919-2343-1c04` | 25.12 | 1,417 | 1.77 |
| P5 | `20260920-0107-4265` | 35.40 | 3,270 | 1.08 |

ADR-H075 본문의 「P5 ≈ 1.06분/100줄」은 35.4분을 **05 패킷의 인라인 diff 줄 수**(3,332,
`05_packet_common.md`)로 나눈 값이다. P2~P4 에는 그 파일이 없어 같은 분모를 쓸 수 없으므로
네 런 모두 `at_05.lines` 로 통일했다 ([ADR-H076](DECISIONS.md) PR 3 추기).

**예측 7·8 의 기준선은 다시 셌다** ([ADR-H076](DECISIONS.md) PR 4 잔여 추기). ADR-H075 본문의 「4런 합 49
(test 리뷰어 47 포함)」은 contract-trace 1건을 섞었고 test 몫(39)을 틀리게 적었다. 「escaped 16 (major 11 ·
minor 23 · critical 0)」은 옛 `escaped_05`(16)와 원장의 07 행 전체(중복·minor 포함 34행)라는 다른 두 양을
한 칸에 섞었다 — 16 은 이 클론의 파일로 재현되지 않아 재현되는 13/9런을 기준으로 한다.

### 채점 규칙 — 런 전에 고정한다

런 뒤에 정하면 채점이 아니라 해석이다. 기준선이 여러 런의 합이면 **런당 값**으로 비교한다.

| # | 셈 | 판정 |
|---|---|---|
| 1·2·3·5 | 08 이 내는 값 그대로 | 표의 부등호 |
| 4 | `state.phase_durations` 의 03·04 `wall_sec` 합(분) ÷ `state.precheck.at_05.lines` × 100 | ≤ 1.86 |
| 6 | 라운드 전부의 gen `findings` 중 severity `critical` — category 와 제목 한 줄씩 | 목록을 적는다. 작성자의 논리 오류면 되돌림 조건 3 |
| 7 | 08 「07 escaped」의 `dup_05=false` 중 Major+ 건수 | 1.44 를 넘으면(= 2건 이상) 되돌림 조건 4 |
| 8 | 라운드 전부의 gen `findings` 중 `category == "TEST_MISSING_FAILURE_PATH"` **정확 일치**, 같은 `keys[].key` 는 한 번 | 12.0 이상이면 「줄지 않았다」 — 되돌림 조건 2. P2~P5 의 폭(5~15)을 결과 칸에 같이 적는다 |

라운드 전부는 `state.phases["05-code-review"].rounds["1"|"2"|…]["gen"]` 다 — `05_review_gen.json` 은
라운드마다 덮어쓰여 마지막 라운드만 남는다([ADR-H076](DECISIONS.md) 결정 5).

**되돌림 조건** (ADR-H075 그대로):

- 예측 4 가 기준 × 1.3 을 넘으면 `roles[]` 에 `test` 를 다시 넣는다(순차 test → impl).
- 예측 8 이 기준선 대비 줄지 않으면 「블라인드 작성자의 산물」 가설이 틀린 것이다 — 백로그 29 의
  처방(`nothing_locked` 기계 검사)을 되살린다.
- 예측 5 가 빗나가거나(04 수리 > 1회) 작성자의 논리 오류로 gen 이 Critical 을 내면 2런에서
  `impl-writer` 의 프론트매터 한 줄(`model: sonnet` → `opus`)로 올려 두 런을 비교한다.
- 예측 7 이 초기 15런 기준선을 넘으면 리뷰어를 늘리지 말고 gen 의 「볼 것」 표에 그 관점의 행을
  더한다 — 그래도 새면 `reviewers[]` 에 둘째를 넣는다.
